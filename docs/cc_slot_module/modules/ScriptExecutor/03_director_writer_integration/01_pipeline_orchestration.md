# 🎼 ScriptExecutor Deep Pipeline Orchestration & Engine Internals

## 1. Architectural Philosophy: The Asynchronous Command Dispatcher

`ScriptExecutor` (`assets/cc-common/cc-slot-module/GameMode/Core/ScriptExecutor.ts`) is the **central execution engine** of the Director-Writer pattern in the Cocos Creator Slot SDK.

Slot games contain dozens of interdependent animations that must occur in strict chronological sequence (spinning ➔ stopping column by column ➔ near win border pulses ➔ payline cycling ➔ big win celebration count-ups ➔ wallet roll-ups ➔ free spin transitions).

`ScriptExecutor` transforms **pure declarative data arrays** generated by the Writer into a **deterministic, asynchronous Promise pipeline** on the Director.

```mermaid
graph TD
    subgraph 1. Script Compilation (Writer)
        Data[Server playSession Data] --> MakeScript[writer.makeScriptAction data]
        MakeScript --> ActionArray["Array of Steps:<br/>[{ command: 'STOP_REEL', data },<br/> { command: 'SHOW_WIN', data, isSkippable: true }]"]
    end

    subgraph 2. Queue Ingestion (ScriptExecutor.runAction)
        ActionArray --> Queue["this.scripts[actionName] = {<br/> actions: [...listScripts],<br/> onFinish: resolve,<br/> onSkip: reject<br/>}"]
    end

    subgraph 3. Step Loop (executeNextScript & runCommand)
        Queue --> Shift[Shift next action from array]
        Shift --> SpeedRoute["getCommandName(command):<br/>Check command_2 -> command_1 -> command"]
        SpeedRoute --> ExecDirect["await director[targetCommand](action.data)"]
        ExecDirect --> LoopCheck{Actions remaining in queue?}
        LoopCheck -->|Yes| Shift
        LoopCheck -->|No| Finish["onFinishScript(actionName):<br/>Trigger onFinish() & delete scripts[actionName]"]
    end

    subgraph 4. Skip & Abort Engine (onResetScript)
        SkipClick[Player clicks Fast Stop / Skip] --> ResetHook["convertAction('_reset', command):<br/>Replaces skippable commands with _resetCommand"]
        ResetHook --> Shift
    end
```

## 2. Exhaustive Step-by-Step Execution Lifecycle

### Phase 1: Action Dispatch (`runAction`)
When the director calls `await this.runAction("SpinResult", data)`:
1. **Validation**: Checks if `this.writer["makeScript" + actionName]` exists. If missing, logs error `makeScript[ActionName] is not a valid action` and aborts.
2. **Compilation**: Invokes the writer synchronously: `const listScripts = this.writer["makeScript" + actionName](data)`.
3. **Queue Container Setup**: Initializes state tracking:
   ```typescript
   this.scripts[actionName] = [];
   this.scripts[actionName].actions = listScripts;
   this.scripts[actionName].onSkip = () => { ... reject(new Error("Handle Back To Real Mode")); };
   this.scripts[actionName].onFinish = () => { ... resolve(); };
   ```
4. **Initiation**: Calls `this.executeNextScript(actionName)`.

---

### Phase 2: Sequential Step Execution (`executeNextScript` & `runCommand`)
1. **Queue Check**: If `this.scripts[actionName].actions` is empty, invokes `this.onFinishScript(actionName)` and resolves the master action Promise.
2. **Command Dequeue**: Shifts the first action object: `const action = this.scripts[actionName].actions.shift()`.
3. **Dynamic Speed Routing (`getCommandName`)**:
   `ScriptExecutor` inspects the active `gameSpeed` and queries the director for speed-suffixed methods:
   * If `gameSpeed === 2` (FTR / Instantly) and `director["STOP_REEL_2"]` exists ➔ Dispatches `"STOP_REEL_2"`.
   * Else if `gameSpeed === 1` (Turbo) and `director["STOP_REEL_1"]` exists ➔ Dispatches `"STOP_REEL_1"`.
   * Else ➔ Dispatches base `"STOP_REEL"`.
4. **Execution & Awaiting**: Dispatches `this.director[command](action.data)`:
   * When the returned Promise resolves, the `.then()` handler immediately triggers `this.executeNextScript(actionName)`.

---

### Phase 3: Fast-Stop, Skips & Interruption (`onResetScript`)
When a player clicks Skip or Turbo Fast-Stop during an in-flight action:
1. `onResetScript(actionName)` is called.
2. `ScriptExecutor` scans all remaining actions in `this.scripts[actionName].actions`:
   * If `action.isSkippable !== false`, it converts the command using `convertAction("_reset", command)` (e.g. `SHOW_PAYLINES` ➔ `_resetShowPaylines`).
   * If the director implements `_resetShowPaylines`, the action is replaced with the instant cleanup method.
   * If `isSkippable === false` (e.g. wallet balance commit), the command is preserved in the queue and executed in full.
3. The modified queue executes immediately to bring the game to a clean rest state.

---

### Phase 4: Emergency Teardown (`forceToExit` & `onResetAllScripts`)
When transitioning back to Real Mode or handling abrupt disconnection:
1. `forceToExit(script)` sets `this.forceToExitMode = true`.
2. `onResetAllScripts()` iterates through every active queue in `this.scripts`, triggers their `onSkip()` rejections, and deletes all internal array references.
3. All pending action promises reject with `Handle Back To Real Mode`, which is caught cleanly by `ScriptExecutor` without throwing unhandled exceptions to the engine.

## 3. Method Naming & Regex Transformation Table (`convertAction`)

`ScriptExecutor.convertAction(prefix, originalName)` dynamically converts command strings into camelCase method identifiers:

| Command String | Conversion Call | Resulting Method Name on Director |
| :--- | :--- | :--- |
| `"SpinResult"` | `convertAction("_reset", "SpinResult")` | `"_resetSpinResult"` |
| `"STOP_REEL"` | `convertAction("_reset", "STOP_REEL")` | `"_resetStopReel"` |
| `"SHOW_PAYLINES"` | `convertAction("_reset", "SHOW_PAYLINES")` | `"_resetShowPaylines"` |
| `"SHOW_BIG_WIN"` | `convertAction("_reset", "SHOW_BIG_WIN")` | `"_resetShowBigWin"` |
| `"COLLECT_COIN"` | `convertAction("_reset", "COLLECT_COIN")` | `"_resetCollectCoin"` |

## 5. Why this Decoupling is Essential for Slot Games

1. **Elimination of Callback Hell**: Without `ScriptExecutor`, coordinating reel stops, near-win teasers, multiple payline cycles, big win coin rolls, and free spin transitions would require deeply nested callbacks or fragile `setTimeout` chains.
2. **Speed Adaptability on the Fly**: If the player toggles Turbo midway through a spin, `ScriptExecutor` seamlessly switches subsequent steps to their `_1` (Turbo) or `_2` (FTR) method variants without restarting or corrupting the queue.
3. **Deterministic Aborts on Skip**: When the player clicks Fast Stop or returns to Real Mode, `ScriptExecutor.onResetScript()` automatically converts pending steps into their instant `_reset[Command]` counterparts.
